# image-to-model — turn reference images into printable models

Use this skill when a project has reference images (in `projects/<name>/refs/`) and the goal
is a printable STL/3MF designed *from* them — "make this into a print", "design something
from this picture", a new image appears in refs and the user says "look at that".

## Where the pictures come from

- **Dropped / imported** by the user (📸 captures, drag-and-drop, 🔗 url) — photos,
  drawings, logos. Anything goes; classify it below.
- **Generated by the studio** — the user (or a child in kid mode) asks for a subject and
  picks one of **4 options** (`options` in `studio.config.json`). The picture library lives
  in `projects/library/refs/gen_<slug>*.png`. Which backend drew it changes what you have:
  - **Claude backend** (`image_backend: "claude"`, Opus 5.5 by default): the picture began
    as an SVG and the vector is kept at **`vectors/<same stem>.svg`** next to `refs/`.
    Prefer it over the PNG — the paths are exact outlines with flat fills, so parse them
    into polygons (one per fill colour) instead of thresholding pixels. Each option also
    has a short `title`.
  - **ComfyUI** (Z-Image Turbo) or **Nano Banana**: raster only. Trace it.
  - **Style**: `sticker` pictures are a single subject in 3–4 flat colours on white — ideal
    for coins, cutouts and multi-color plates. `turnaround` pictures show the same subject
    from the front, side profile and three-quarter — use the views for proportions when
    building in the round.

## Step 1 — Read every image in refs/, then classify the job

Look at the images first. Decide which of these the target is, and say which you picked:

| Type | Signals in the image | Build strategy |
|---|---|---|
| **Coin / token** | a sticker-style subject wanted small and quick | don't hand-build it: `studio/tools/make_coin.py` (the token-coin skill) |
| **Flat cutout / stencil** | logo, silhouette, line art | threshold → vectorize outline (opencv/shapely) → extrude 2–6 mm |
| **Relief / plaque** | photo or drawing to hang/display | grayscale → heightmap → displaced grid on a base plate |
| **Traced photo plaque** | photo of real people wanted as raised line art ("trace us") | **Trace, never redraw.** Asking an image model for "line art of this photo" invents eyes, mouths and hair — people notice and reject it. Instead: mask the people off the background (green-screen / segmentation), run a line-art extractor on the real pixels, ink that trace, then **overlay it on the photo before showing** so the user can check it |
| **Multi-color plate** | line art with distinct color regions (like a coloring-book page) | split into per-color regions → one mesh per color in `parts/` + `parts.json`, deliver 3MF |
| **Functional part** | photo of an object to replace/fit (bracket, clip, connector) | parametric `design.py` from measured/asked dimensions — the image is for proportions |
| **Full 3D figurine / toy** | character/object wanted "in the round" (a "Make me 3D" build) | hardest; from a turnaround sheet or a single picture → stylized parametric approximation (blocky primitives, booleans) or a relief; be honest about limits and offer the relief option |

## Step 2 — Ask only the questions the image can't answer

Batch them in ONE message; propose defaults so the user can just say "yes":

1. **Real-world size** — the one thing never inferable. Propose a number ("nameplate width
   160 mm?").
2. **Where it lives** — desk / wall (needs hanger hole?) / fits onto something (get the
   mating dimension).
3. **Colors** — single color, or CFS multi-color? If multi: which image colors map to which
   filament (≤ 4 per CFS).
4. **Anything load-bearing?** — decorative vs functional changes walls/infill later.

Skip questions when refs or chat already answer them. Never block on nice-to-knows —
default and note the assumption. A headless "Make me 3D" build asks nothing: its prompt
already fixes the size range, the age of the child, and "no supports".

## Step 3 — Build v1 fast, iterate in the studio

- Scaffold per the design-studio skill; write `design.py` (or a one-off build script for
  relief/vectorize jobs — still saved in the project folder so it can be rerun).
- Useful toolbox already in `.venv`: `opencv-python-headless` (threshold, contours),
  `scikit-image` (marching squares), `shapely` (polygon cleanup, buffer), `trimesh`
  (`extrude_polygon`, booleans via manifold3d), `pillow`, `resvg_py` (render an SVG to a
  PNG when you want to compare against the picture).
- Ship a rough v1 to the viewer within a few minutes, then refine from the user's reactions
  and captures. Don't polish before they've seen the silhouette at all.
- Sanity-check printability as you go: feature width ≥ 0.8 mm (2 walls), text emboss/deboss
  ≥ 0.4 mm deep, bridges < 10 mm, overhangs — flag anything that needs supports. For a
  child's toy go chunkier: ≥ 1.2 mm everywhere, no thin spikes.

## Step 4 — Multi-piece / multi-color output

- One watertight mesh per color, all in **shared bed coordinates** so they stack correctly,
  exported to `parts/<piece>.stl` + `parts.json` with display hexes. The studio paints
  each part separately, so a merged mesh can't be recoloured.
- Pieces must not z-fight: separate them in Z (base plate + inlay lines) or make regions
  butt cleanly in XY.
- Deliverable: 3MF via the k2-slicing skill's CFS workflow, plus channel assignments
  (which filament in which CFS slot).

## Finish

Repair/verify with stl-prep, copy deliverables to `final/`, update `MANIFEST.md` if the repo
keeps one, quote PLA settings per k2-slicing (or the active printer's
`printers/<slug>/profile.md`).
